**Модель прогнозирования оттока клиентов банка**

**Версия документа:** 1.0  
**Дата составления:** 2 ноября 2026 г.  
**Тип модели:** Binary Classification  
**Алгоритм:** CatBoost Classifier

---

## 1. Model Details — Сведения о модели

### 1.1. Основная информация

| Параметр | Описание |
|---|---|
| Название | Bank Customer Churn Prediction |
| Тип задачи | Бинарная классификация |
| Область применения | Банковская деятельность, CRM, аналитика клиентов |
| Алгоритм | CatBoost Classifier |
| Библиотека | CatBoost |
| Метод оптимизации | Optuna |
| Целевая переменная | Exited |
| Формат результата | Вероятность оттока клиента |



### 1.2. Архитектура и принцип работы

Модель использует алгоритм CatBoost — градиентный бустинг на решающих деревьях.

Процесс построения модели включает следующие этапы:

1. Загрузка и первичный анализ данных.
2. Исследовательский анализ данных (EDA).
3. Генерация дополнительных признаков (Feature Engineering).
4. Предварительная обработка данных.
5. Разделение данных на обучающую и тестовую выборки.
6. Оптимизация гиперпараметров с помощью Optuna.
7. Обучение итоговой модели CatBoost.
8. Получение вероятностей оттока клиентов.

### 1.3. Гиперпараметры

Для оптимизации использовались следующие параметры:

- iterations: от 100 до 1000;
- learning_rate: от 0.01 до 0.3;
- depth: от 4 до 10;
- l2_leaf_reg: от 0.1 до 10;
- border_count: от 32 до 255;
- bagging_temperature: от 0 до 1;
- random_strength: от 10⁻⁹ до 10;
- grow_policy: SymmetricTree, Depthwise или Lossguide.

Оптимизация проводилась в течение 100 испытаний Optuna с целью максимизации ROC-AUC.

### 1.4. Используемые признаки

Исходные признаки:

- CreditScore — кредитный рейтинг;
- Geography — страна проживания;
- Gender — пол;
- Tenure — срок обслуживания в банке;
- Balance — баланс счёта;
- HasCrCard — наличие кредитной карты;
- IsActiveMember — активность клиента;

Дополнительно создаются признаки:

- AgeGroup — возрастная группа;
- WealthIndex — индекс благосостояния;
- ZeroBalance — наличие нулевого баланса;
- SalaryPerYear — отношение заработной платы к возрасту;
- EstimatedSalaryDiff — отношение медианной зарплаты возрастной группы к зарплате клиента;
- AvgCountryBalance — средний баланс по стране;
- AgeTenureRatio — отношение возраста к сроку обслуживания;
- HasCardAndActive — наличие карты и активность одновременно;
- LogEstimatedSalary — логарифм заработной платы;
- AgeSquared — квадрат возраста;
- QuantityProducts — категория по количеству продуктов.

Идентификаторы клиентов и фамилии исключаются из моделирования.

## 2. Intended Use — Назначение

### 2.1. Основное назначение

Модель предназначена для прогнозирования вероятности ухода клиента из банка на основе его социально-демографических, финансовых и поведенческих характеристик.

Основная бизнес-задача — выявление клиентов с повышенной вероятностью оттока для последующего анализа и применения мероприятий по удержанию.

### 2.2. Предполагаемые пользователи

- Аналитики банковских данных;
- специалисты CRM;
- сотрудники подразделений по работе с клиентами;
- специалисты по управлению клиентским опытом;
- исследователи в области машинного обучения.

### 2.3. Допустимые сценарии использования

1. Анализ факторов, связанных с оттоком клиентов.
2. Формирование предварительного списка клиентов для дополнительного анализа.
3. Исследование закономерностей клиентского поведения.
4. Оценка вероятности оттока на уровне отдельного клиента.
5. Поддержка разработки программ удержания клиентов.

## 4. Metrics — Метрики качества

### 4.1. Основная метрика

ROC-AUC (Area Under the Receiver Operating Characteristic Curve).

Данная метрика выбрана в качестве целевой при подборе гиперпараметров.

ROC-AUC оценивает способность модели правильно ранжировать клиентов с точки зрения вероятности оттока независимо от конкретного порога классификации.

### 4.2. Метод оценки

Для оптимизации гиперпараметров используется:

- Stratified cross-validation ;
- 5-кратная кросс-валидация (`cv=5`);
- 100 испытаний Optuna;
- критерий максимизации среднего ROC-AUC.

Дополнительно данные разделяются на обучающую и тестовую выборки в соотношении 70/30 с `random_state=42`.

### 4.3. Результаты

| Показатель | Результат |
|---|---|
| Целевая метрика | ROC-AUC |
| Количество испытаний Optuna | 100 |
| Количество фолдов | 5 |
| Лучший ROC-AUC | 0.9322004812841034 |
| Порог классификации | 0.5 |



### 4.4. Рекомендуемые дополнительные метрики

Для более полной оценки рекомендуется рассчитать:

- Precision — точность выявления ушедших клиентов;
- Recall — полнота выявления ушедших клиентов;
- F1-score — баланс Precision и Recall;
- PR-AUC — качество ранжирования при дисбалансе классов;
- Confusion Matrix — матрица ошибок;
- Brier Score — качество вероятностных прогнозов.

Порог принятия решения необходимо определять с учётом стоимости ошибочного прогноза и затрат на удержание клиента.

Из признакового пространства удаляются:

Обучение проводится на преобразованных данных.

- random_state = 42.

Для подбора гиперпараметров применяется 5-кратная кросс-валидация на обучающей части.

## 8. Ethical Considerations — Этические аспекты

### 8.1. Конфиденциальность

Модель использует финансовые и персональные характеристики клиентов.

При практическом применении необходимо обеспечить защиту персональных данных, ограничить доступ к исходной информации и соблюдать требования законодательства о персональных данных.

Идентификаторы и фамилии клиентов исключены из признаков модели, однако это само по себе не гарантирует анонимность данных.

### 8.2. Алгоритмическая предвзятость

Использование возраста, пола и географического положения может приводить к различиям в прогнозах для отдельных категорий клиентов.

Нельзя считать, что высокая общая точность автоматически означает справедливость модели.

### 8.3. Последствия ошибочных прогнозов

Возможны два основных типа ошибок:

- False Positive — клиент прогнозируется как склонный к уходу, хотя фактически остаётся;
- False Negative — клиент прогнозируется как остающийся, хотя фактически уходит.

Первый тип может привести к нецелевым затратам на удержание, второй — к потере клиента и потенциальной выручки.

### 8.4. Рекомендации по ответственному применению

- Использовать прогноз как вспомогательную информацию.
- Не принимать автоматические решения, существенно влияющие на права клиента.
- Проводить регулярный аудит качества и справедливости.
- Контролировать изменения распределения данных.
- Обеспечивать защиту персональных данных.
- Предусмотреть возможность проверки прогнозов специалистом.
